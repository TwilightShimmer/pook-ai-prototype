低龄课堂进度表达与BrainAgent动态流程PRD

阅读说明 先看结论，再看细节。

这份文档围绕《低龄课堂进度表达与BrainAgent动态流程PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

这份需求在解决：课堂进度到底该怎么让孩子、老师和系统同时看懂的问题。

02

这份需求值得做：它会直接影响低龄课堂的节奏感、理解感和 BrainAgent 后续能力边界。

03

这份需求体现的产品判断：儿童端应该看任务阶段，系统端应该看时间节奏，不能只做死流程或纯计时。

1. 背景

课堂进度不是一个小 UI。 它会直接影响：

  1. 孩子能不能看懂自己现在在做什么
  2. 老师能不能把握课堂节奏
  3. BrainAgent 后续能不能动态调整流程

我不希望产品被固定流程节点绑死。 但我也不接受只剩一个计时器。

2. 问题定义

2.1 只用完整流程节点的问题

  • 太像流程图
  • 低龄儿童认知负担大
  • 容易把流程误解成死顺序

2.2 只用时间的问题

  • 孩子知道时间在走
  • 但不知道任务是否完成

2.3 BrainAgent 相关问题

如果后续 BrainAgent 要动态调度，前端就不能把流程表达成一条完全固定的铁轨。

3. 目标

我希望同时满足两件事：

  1. 孩子知道现在在做什么
  2. 系统和老师知道节奏进行到哪里

一句话说：

儿童端看任务阶段，系统端看时间节奏。

4. 版本范围

本需求主要覆盖：

  1. 课堂进度组件
  2. 环节切换提示
  3. 自由拼搭的时间收束
  4. BrainAgent 后续动态流程的前端承接方式

5. 方案设计

5.1 局部流程提示

页面底部不展示完整流程。 只展示：

  1. 上一个节点
  2. 当前节点
  3. 下一个节点

5.2 局部动画倒计时

我不建议全流程倒计时。 只在需要收束的环节使用。

优先环节：

  • 自由拼搭

表达方式：

  • 用动画视觉进度代替纯数字
  • 比如花朵点亮、能量条填满、角色完成准备

5.3 正计时作为系统侧记录

系统和老师侧保留正计时，用来：

  1. 记录总时长
  2. 记录环节耗时
  3. 支持 BrainAgent 后续调度

6. 关键规则

  1. 儿童端只看当前相关任务
  2. 局部流程提示是状态提示，不是导航菜单
  3. 当前节点最大、最突出
  4. 倒计时只用于需要收束的环节
  5. 系统端保留时间记录能力
  6. 节点定义应偏向任务状态，而不是固定页面顺序

7. 数据与状态要求

需要至少支持：

  1. 当前步骤
  2. 已完成步骤
  3. 下一步骤
  4. 当前环节提示文案
  5. 环节计时记录
  6. 是否需要收束的环节标记

8. 验收标准

  1. 儿童端只看到当前相关任务
  2. 自由拼搭支持局部倒计时
  3. 流程组件不被理解成跳转导航
  4. 系统端能保留时间记录能力
  5. 后续 BrainAgent 接入时，不需要推翻整个进度组件结构

9. 暂不纳入

这轮先不做：

  1. 全流程统一倒计时
  2. 速度导向排行榜
  3. 复杂的课堂算法判断

时间机制先服务课堂节奏，不先做竞速系统。
