价值摘要

01

把“展示积木清单”改成“POKI带孩子完成视觉匹配”。

02

技术上先降维：不识别积木形状，只识别颜色块和数量。

03

减少老师被反复询问，把确认权部分交给屏幕反馈。

1. 真实场景

屏幕展示本次课程要用的积木形状和颜色。小朋友们在积木盒子里翻找对应积木块。

实际发生的问题是：孩子经常找不到；即使找到了，也会不确定是不是 POKI 要求的积木，于是反复向老师确认。

2. 问题定义

  1. 孩子缺少判断标准：不知道先看颜色、形状还是数量。
  2. 积木盒视觉信息太复杂，低龄孩子容易被干扰。
  3. 老师承担了大量“对不对”的确认工作。
  4. 直接识别具体积木形状技术风险高，不适合作为当前版本核心能力。

3. 产品目标

把找积木环节设计成一个“颜色数量确认任务”。

孩子看屏幕目标，在盒子里找到对应颜色和数量的积木，举起来给 POKI 看，POKI 先做颜色和数量确认。

4. 页面流程

4.1 进入环节：POKI先说明

POKI 弹出并用幼教口吻说明：

宝贝们，我们要找积木啦。先看颜色，再找出来。找好以后，举起来给 POKI 看一看。

屏幕只保留三个动作：看颜色 → 找积木 → 举起来。

4.2 顶部：当前阶段流程

大容器最上方展示当前找积木进度，例如：

白色 → 蓝色 → 黄色 → 完成

当前目标高亮，完成后点亮。

4.3 大容器左侧：当前目标积木

左侧只展示当前要找的一组积木：

  • 颜色块
  • 大积木示意图
  • 数量
  • 短句：找 4 个白色

4.4 大容器右侧：视频流确认区

右侧展示视频流，提示孩子：

举起来给 POKI 看

视频流里可以有一个识别框，帮助孩子知道应该把积木放到哪里。

5. 识别策略

当前版本不做具体积木形状识别，只做低风险判断：

  1. 颜色是否接近目标颜色。
  2. 数量是否接近目标数量。
  3. 画面中是否有明显积木色块。

例如目标是 4 个白色积木，只要摄像头看到孩子举起了 4 个左右白色积木，就给通过反馈，不强行判断具体形状。

6. 反馈规则

  • 颜色正确且数量接近：白色找齐啦，我们去找下一个。
  • 颜色正确但数量不足：白色对啦，还差 1 个。
  • 颜色不对：颜色不太像，我们再找白色。
  • 画面不清楚：举高一点，POKI 再看一眼。

7. 计时策略

建议使用正计时，而不是强倒计时。

原因：

  1. 4-6 岁孩子对倒计时理解不稳定，容易只感受到压力。
  2. 找积木耗时受真实积木盒状态影响，不适合强制倒计时失败。
  3. 老师更需要知道当前环节已经花了多久。

建议显示：

正在找白色 00:32 / 建议 40 秒内完成

超过建议时间后，POKI 温和提醒；超过较长时间后，给老师轻提示。

8. 验收标准

  1. 进入环节时，POKI 会先说明任务。
  2. 页面一次只展示一个当前目标积木组。
  3. 页面同时具备目标展示区和视频确认区。
  4. 识别逻辑按颜色和数量判断，不强依赖形状识别。
  5. 找对后点亮当前阶段，并进入下一个目标。
  6. 计时采用正计时 + 温和提醒。
