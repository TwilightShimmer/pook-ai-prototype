各课程环节自动化与简单化设计原则PRD

阅读说明 先看结论，再看细节。

这份文档围绕《各课程环节自动化与简单化设计原则PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

解决 4-6 岁小朋友和幼儿园保育老师在课堂中不适合复杂操作的问题。

02

这份 PRD 不是新增某个页面，而是给每一个课程环节补上统一的交互原则。

03

核心判断：产品要主动承担流程组织，不能把课堂推进压力丢给小朋友和保育老师。

1. 背景

我们的目标用户主要是 4-6 岁小朋友，以及幼儿园里的保育老师。

这两类用户都不适合使用复杂系统。

  • 小朋友不一定识字，也不一定能听懂抽象问题。
  • 小朋友的注意力短，很容易不知道自己现在该做什么。
  • 保育老师不是专业课程操作员，不应该被迫处理复杂配置。
  • 课堂现场会有噪音、走神、抢操作、等待、找不到材料等真实问题。

所以课程产品的设计原则必须完全遵从两个关键词：

  • 自动化
  • 简单化

2. 问题定义

现在已有 PRD 已经定义了一部分课程流程，但还缺少每个课程环节的交互细节原则。

如果只定义“有哪些环节”，但不定义“每个环节应该怎么让低龄儿童和保育老师轻松完成”，后续开发会很容易做成一个成人视角的流程系统。

这会带来几个问题：

  • 小朋友不知道当前屏幕要他们做什么。
  • 老师需要不断点击、判断、解释，课堂负担变重。
  • 自由发挥变成无引导的放空。
  • 多人上课时容易出现一个孩子一直操作，其他孩子插不上手。
  • 系统流程看似完整，但真实课堂跑不起来。

3. 产品目标

这份 PRD 要补齐的是全课程流程的交互原则。

目标不是让系统功能更多，而是让系统更少依赖人工推动。

  • 每一屏只表达一个任务。
  • 每个环节只保留一个主动作。
  • 默认由系统自动推进流程。
  • 老师只负责必要确认和异常兜底。
  • 小朋友不用读长文字，也不用理解复杂规则。
  • 反馈必须快、直观、可感知。

4. 适用范围

本原则适用于以下课程环节：

  • 选课
  • 见面识别
  • 欢迎
  • 今日目标
  • 问答互动
  • 找积木
  • 固定拼搭
  • 自由拼搭
  • 分享展示
  • 成长记录 / 纪念卡发放

5. 总体设计原则

5.1 一屏一个目标

每一屏只让小朋友理解一件事。

不要在同一屏里同时放课程说明、任务说明、奖励说明、流程说明和操作说明。

低龄儿童不是在读系统界面，他们是在被画面、声音和动作引导。

5.2 一个环节一个主动作

每个环节最多保留一个主动作。

比如：

  • 选课：点当前推荐课程
  • 找积木：找出当前这一种积木
  • 拼搭：完成当前这一步
  • 分享：轮到自己说一句

如果一个环节出现多个同级按钮，优先级就会变模糊。

5.3 默认自动推进

课程流程不应该依赖老师连续点击才能继续。

系统应默认自动完成：

  • 环节进入
  • 状态切换
  • 任务播报
  • 结果反馈
  • 下一环节推进

老师只在系统无法判断、需要安全确认、或需要临时干预时介入。

5.4 图像、语音、动画优先

4-6 岁小朋友不能被当成稳定阅读用户。

优先级应该是：

  1. 图像
  2. 动画
  3. 语音
  4. 大图标
  5. 短文字

文字可以存在，但不能成为理解任务的唯一入口。

5.5 老师控制项极简

保育老师不应该面对复杂后台。

课堂中最多保留四类兜底操作：

  • 暂停
  • 继续
  • 跳过
  • 重试

不要让老师在课堂现场处理多层设置、长表单、复杂规则选择。

5.6 失败反馈不惩罚

小朋友做错时，系统不应该制造挫败感。

反馈方向应该是：

  • 不是这个，再看看颜色。
  • 差一点点，我们换个角度看。
  • 先找这个形状。
  • 轮到下一位小朋友试试。

错误要变成引导，不要变成失败。

6. 各课程环节设计原则

6.1 选课环节

选课页不应该要求小朋友理解完整课程体系。

系统默认展示当前最推荐、最适合进入的课程。

设计原则：

  • 默认突出当前可上的最新课程。
  • 未解锁课程可以看见，但不能成为主要干扰。
  • 点击未解锁课程时，只给轻提示，不打断流程。
  • 老师最多选择主题或课程，不承担复杂路径判断。
  • 小朋友看到的重点应该是“跟 POKI 上这节课”。

6.2 见面识别环节

见面环节是课程正式开始前的自动识别和自动分工。

设计原则：

  • 不提前选择上课人数。
  • 由实际进入画框的儿童人数决定本节课参与人数。
  • 优先识别儿童，不把误入画面的成人计入学生。
  • 最少 1 人，最多 4 人。
  • 识别完成后自动拍照、编号、分配角色。
  • 不要求小朋友或保育老师点击确认。
  • 系统自动进入欢迎环节。

6.3 欢迎环节

欢迎环节不是信息页，而是课堂状态切换。

设计原则：

  • 用角色、声音、主题图像建立“开始上课”的感觉。
  • 内容要短，不做长视频引入。
  • 不要求小朋友读文字。
  • 自动播放后进入今日目标。
  • 老师只需要能暂停或跳过。

6.4 今日目标环节

今日目标要回答一个问题：今天我们要完成什么。

设计原则：

  • 用一张大图或一个简单动画表达目标。
  • 目标要具体，不要抽象。
  • 不说“培养工程思维”这种成人语言。
  • 可以表达为“今天帮犀牛洗澡”“今天让小车跑起来”。
  • 展示完成后自动进入下一环节。

6.5 问答互动环节

问答环节不能假设小朋友听得懂复杂问题，也不能假设他们能读字。

设计原则：

  • 一次只问一个问题。
  • 问题必须配图、配语音。
  • 答案尽量用大图按钮、实物识别、口头回答或老师轻确认。
  • 如果小朋友无反应，系统自动换一种说法。
  • 不让小朋友在一堆文字选项里做选择。
  • 问答目标是唤起观察，不是考试。

6.6 找积木环节

找积木环节的重点是降低材料搜索成本。

设计原则：

  • 每次只展示一种当前要找的积木。
  • 大图展示颜色、形状、数量。
  • 找错时给具体提示，比如颜色不对、数量不够、形状接近。
  • 找齐后自动进入拼搭，不需要反复确认。
  • 必要时允许老师一键确认。
  • 不让小朋友一次面对完整材料清单。

6.7 固定拼搭环节

固定拼搭不是说明书搬运，而是一步一步带着孩子完成。

设计原则：

  • 一步一图。
  • 当前步骤永远最大、最清晰。
  • 不展示长段说明。
  • 完成一步后自动或轻确认进入下一步。
  • 多人上课时，要提示轮换角色。
  • 避免一个小朋友一直拼，其他小朋友只能看。

6.8 自由拼搭环节

自由拼搭不能直接等同于“让孩子自己发挥”。

这个年龄段的小朋友需要脚手架。

设计原则：

  • 先给一个明确起点，比如“先加一个会动的部分”。
  • 再给开放空间，而不是一上来完全自由。
  • 用阶段提示引导继续扩展。
  • 设置柔性倒计时，避免无限拖长。
  • 时间快结束时给收束提醒。
  • 到点后自动进入分享，而不是让老师强行打断。

6.9 分享展示环节

分享环节要避免小朋友不知道说什么，也要避免只有一个孩子一直说。

设计原则：

  • 按编号或角色自动轮到每个小朋友。
  • 每个孩子只需要说一句简单内容。
  • 提供句式脚手架，比如“我做的是……”“它可以……”
  • 可以用语音提示代替文字提示。
  • 老师可以跳过害羞或不愿意表达的孩子。
  • 不把分享做成压力测试。

6.10 成长记录 / 纪念卡发放环节

成长记录应该自动沉淀，不应该变成老师的手动填写任务。

设计原则：

  • 完成课程后自动发放宝石奖励。
  • 首次完成课程后自动获得纪念卡。
  • 重复完成同一课程不重复发同一张纪念卡。
  • 每完成一个主题后，可以升级表现最好的课程卡片为闪卡。
  • 成长页展示能力标签、课程记录和纪念卡。
  • 老师不需要手动写大量评语。

7. 保育老师控制原则

保育老师在课堂里不是系统操作员。

老师的操作应该只用于兜底。

建议保留四个课堂控制能力：

  • 暂停：课堂临时中断。
  • 继续：恢复自动流程。
  • 跳过：当前环节无法完成时进入下一环节。
  • 重试：识别失败、找错材料或流程异常时重新来一次。

不要让老师承担这些事情：

  • 提前配置复杂人数。
  • 手动分配每个学生任务。
  • 连续点击推动每一步。
  • 在课堂中填写长表单。
  • 判断复杂奖励规则。

8. 状态与配置要求

每个课程环节都应该有统一的状态配置，方便 BrainAgent 后续接管课程流程。

建议每个环节至少包含：

  • autoAdvance：是否自动推进
  • minDuration：最短停留时间
  • maxDuration：最长停留时间
  • requiresAdultConfirm：是否需要成人确认
  • fallbackPrompt：失败或无反应时的兜底提示
  • teacherControls：老师可用控制项
  • feedbackType：反馈方式，语音、动画、图像或震动

这样后续不是每个页面各自写逻辑，而是把课程环节变成可配置、可被 BrainAgent 调度的流程单元。

9. 验收标准

  • 每个课程环节默认可以自动推进。
  • 每一屏只出现一个最主要任务。
  • 每个环节最多一个主操作。
  • 关键反馈在 1 秒内出现。
  • 小朋友不识字，也能通过图像、语音或动画理解当前任务。
  • 保育老师不需要连续点击推动课堂。
  • 自由拼搭有明确起点、过程提示和结束收束。
  • 多人环节有轮次或角色提示。
  • 成长奖励能自动发放，不依赖老师手动记录。
  • 异常情况有暂停、跳过、重试等兜底操作。

10. 暂不纳入本 PRD

  • 真实摄像头硬件接入方案。
  • 儿童识别算法模型细节。
  • 老师后台完整配置系统。
  • 家长端成长报告。
  • 全量语音识别能力。
  • 真实课堂数据统计后台。
