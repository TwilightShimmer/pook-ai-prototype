PRD / UI开发规范

POOK AI课堂端设计分辨率与平板适配规范

设计按 2200 × 1440 建基准，前端按 2200:1440 做等比适配；核心内容稳定，背景负责兼容。

阅读说明 先看结论，再看细节。

这份文档围绕《POOK AI课堂端设计分辨率与平板适配规范》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

1. 最终结论

基准画布 课堂端 UI 设计稿统一使用 2200 × 1440。
比例 2200:1440 = 55:36，约等于 1.528:1。
适配方式 运行时不把页面写死成 2200px，而是用等比容器缩放。
核心原则 关键按钮、课程内容、进度栏、视频框必须始终在安全区内。
一句话标准：UI 以 2200 × 1440 做统一设计；前端以 2200:1440 做统一适配；不同设备只影响背景延展，不影响核心上课体验。

2. 为什么定 2200 × 1440

  • 当前主要上课设备是一块平板，实际分辨率为 2200 × 1440。
  • 上一版 POOK AI 已经围绕这块平板做过完整设计，沿用它可以减少重新校准成本。
  • 课堂端是强场景产品，不是普通网页。它优先服务“合作机构上课过程”，所以要先保证主设备体验稳定。
  • 统一设计分辨率可以避免两个 UI 设计师交付的背景图、场景图、IP 图大小完全不一致。

3. 设计分辨率到底是什么

设计分辨率不是要求所有设备都必须是 2200 × 1440，也不是要求前端把页面写死成 2200px 宽。

对产品

它是我们判断页面主次、按钮大小、孩子能不能点到的共同尺子。

对 UI

它是所有页面、背景、卡片、IP、动效分镜的统一设计画布。

对前端

它是页面等比缩放、资源裁切、安全区计算和验收测试的基准比例。

4. 页面适配原则

4.1 核心画布

  • 前端应建立一个课堂主容器，比例固定为 aspect-ratio: 2200 / 1440。
  • 主容器在浏览器或 WebView 中水平、垂直居中。
  • 主容器按可用空间等比缩放，不允许横向或纵向单独拉伸。
  • 页面标题、返回按钮、当前小队、积分、设置入口、底部导航栏都必须属于主容器内部，而不是飘在浏览器外层。

4.2 不同设备怎么处理

  • 同尺寸或接近 2200 × 1440 的设备：主容器尽可能铺满屏幕。
  • 更宽的设备：核心画布保持比例居中，两侧可用背景色、场景延展图或非关键信息填充。
  • 更窄或更接近 4:3 的设备：核心画布整体缩放，优先保证按钮、视频框、课程内容不被裁切。
  • 任何设备都不允许把 IP、视频、课程路径、底部进度栏拉变形。

4.3 背景和内容的职责

  • 核心内容负责教学：课程节点、视频画框、POKI 提示、互动按钮、奖励反馈。
  • 背景负责兼容：不同设备多出来的空间由背景承接，不放关键操作。
  • 如果需要做满屏沉浸感，背景可以延展，但核心教学内容仍然按 2200:1440 的安全区布局。

5. 安全区规范

我们的用户是 4-6 岁小朋友和幼儿园保育老师，误触、看不懂、点不到，比页面“好看一点”更影响课堂。

  • 顶部安全区：放标题、返回、当前小队、设置，不放需要孩子高频点击的核心操作。
  • 中部安全区：放当前环节最重要的视觉内容，例如视频画框、积木模型、问题图片、拼搭任务。
  • 底部安全区：放课程进度、上一步、下一步、经验值、星星罐，不得遮挡上方主容器。
  • 边缘安全区：屏幕边缘只放低频入口或装饰，不放必须完成的课堂操作。
  • 触控安全：儿童常用按钮在 2200 × 1440 设计稿中建议不小于 88 × 88，主按钮高度建议 120-160。

6. 资源交付规范

6.1 图片和场景

  • 页面背景图按 2200 × 1440 交付。
  • 关键场景图、课程模型图、活动插图需要标注在画布中的展示位置和裁切方式。
  • POKI/IP 形象不要直接烘焙进背景图，应独立交付透明 PNG/WebP 或动效资源，方便前端做说话、滑入、缩放等状态。
  • 图标优先使用 SVG 或矢量格式，避免在高分屏上发糊。

6.2 视频

  • 视频容器必须保持原始比例，不允许强行拉伸。
  • 课程视频、过场视频、设备测试视频要明确是“完整显示”还是“允许裁切填满”。
  • 播放过场动画时，跳过 icon 应在主容器右上角，不应贴到浏览器窗口角落。

6.3 动效

  • 动效位置以主容器坐标为准，不以浏览器左上角为准。
  • 课程中的星星奖励、POKI 弹窗、右侧信息栏都应在主容器内完成移动和缩放。
  • 动效不能遮挡底部进度栏，也不能让核心任务区域和状态栏发生重叠。

7. 前端实现要求

  • 禁止用大量固定像素去框主内容区，例如把视频框写死成某个固定宽高后不随容器变化。
  • 课程主容器建议使用 CSS 变量统一管理：画布比例、顶部高度、底部高度、内容间距、安全边距。
  • 主容器内部可以用百分比、grid、flex、aspect-ratio、clamp 等方式布局。
  • 需要滚动的页面，滚动发生在主容器内部，而不是让整个浏览器页面随意滚动。
  • 所有 overlay、toast、视频过场、二级确认弹窗，都必须挂在主容器坐标系内。

8. 测试设备与视口

至少用以下视口验收一次，重点看核心内容是否被裁切、遮挡、拉伸。

  • 2200 × 1440：主设备基准。
  • 1920 × 1200：常见 16:10 平板或笔记本视口。
  • 2048 × 1536：接近 4:3 的 iPad 类设备。
  • 2560 × 1600：更宽的高分屏设备。
  • 浏览器窗口缩放：检查主容器是否仍然居中，标题和底部导航是否还在容器内。

9. 验收标准

  1. 页面 title、返回按钮、当前小队、积分、设置入口、底部导航栏全部在主容器内。
  2. 课程大容器和底部进度栏相互独立，不发生遮挡。
  3. 视频、图片、POKI/IP 形象不被横向或纵向拉变形。
  4. 儿童需要点击的按钮足够大，且不贴边。
  5. 换不同设备后，最多只出现背景留白或背景延展，不出现关键内容丢失。
  6. UI 设计稿、前端实现、验收截图都能回到同一个基准：2200 × 1440。

10. 分工边界

  • 产品：定义设计分辨率、关键安全区、课堂核心任务优先级。
  • UI：按 2200 × 1440 输出设计稿，标注安全区、组件尺寸、资源切图规范。
  • 前端：按 2200:1440 建主容器，保证所有页面元素跟随容器适配。
  • 测试：按测试视口验收，不只看当前电脑浏览器是否正常。
