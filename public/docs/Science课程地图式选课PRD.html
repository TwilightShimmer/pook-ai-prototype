Science课程地图式选课PRD

阅读说明 先看结论，再看细节。

这份文档围绕《Science课程地图式选课PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

这份需求在解决：课程选择过于像列表，不像低龄用户可理解的闯关入口的问题。

02

这份需求值得做：它会影响孩子是否愿意开始课程，以及后续解锁、收藏和成长机制能不能自然接上。

03

这份需求体现的产品判断：低龄选课应该是地图式关卡，不应该是后台式课程列表。

1. 背景

我不希望课程选择还是普通卡片列表。 尤其在低龄产品里，选课不应该像在看后台菜单。

我希望它更像：

关卡地图

而不是：

课程列表

2. 问题定义

当前选课方式的问题主要有三类：

  1. 不够像闯关，更像浏览列表
  2. 主题分类不够有层次
  3. 后续解锁、收藏、成长体系很难自然接上

3. 目标

我希望这部分同时满足四件事：

  1. 让孩子知道“我可以从哪一节开始”
  2. 让课程更有闯关感
  3. 让主题分类更清楚
  4. 给后续解锁机制和收藏机制留接口

4. 版本范围

本需求覆盖：

  1. Science 主题选课页
  2. 左侧主题切换结构
  3. 课程节点地图
  4. 默认解锁与锁定交互
  5. 滚动切换主题

5. 方案设计

5.1 左侧课程主题书签

主题不做横向标签。 保持左侧书签式结构。

当前主题：

  • 从左边拔出来
  • 展示完整内容

未选主题：

  • 收回去
  • 只展示弱化态

默认进入：

  • 生命科学

主题包括：

  • 生命科学
  • 自然科学
  • 工程科学
  • 社会人文

5.2 中间课程地图

每个主题下先展示 5 个课程节点。 节点不应该笔直排成列表。

应该做成：

  • 蜿蜒路径
  • 小球节点
  • 节点之间有连接关系

默认规则：

  • 先解锁最简单的一节课
  • 其余节点先锁定

6. 关键规则

6.1 默认解锁规则

每个主题默认只开放第一节课。

6.2 锁定规则

未解锁课程点击后，不进入课程。 系统通过 toast 提示孩子先选当前已解锁课程。

6.3 引导规则

当前已解锁的最新课程，需要有明确引导。

要求：

  • 可用 POKI 临时替身形象
  • 文案短
  • 指向当前可上的一节课

6.4 滚动切换规则

  1. 当前主题内容区支持上下滚动
  2. 滑到底后继续下滑，切到下一个主题
  3. 滑到顶后继续上滑，切回上一个主题
  4. 切换后回到新主题顶部

7. 数据要求

每节课至少需要这些字段：

  1. 课程名
  2. 所属主题
  3. 课程图形 / 视觉
  4. 课程等级
  5. 是否解锁
  6. 是否当前推荐

后续建议预留：

  1. 是否已完成
  2. 是否获得纪念卡
  3. 是否为该主题闪卡来源

8. 验收标准

  1. 左侧主题是书签式，不是横向 chip
  2. 课程节点是地图感，不是直线列表
  3. 默认只有第一节课可上
  4. 未解锁节点点击会提示
  5. 当前推荐节点有明显引导
  6. 主题内容区支持滚动切换

9. 暂不纳入

这轮先不做：

  1. 复杂解锁树
  2. 多层分支地图
  3. 课程结算与收藏体系联动

先把基础的地图式选课跑顺。
