成长系统与数字展馆PRD

阅读说明 先看结论，再看细节。

这份文档围绕《成长系统与数字展馆PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

成长中心现在不是“记录页 + 展馆页”两个页面，而是一本书里的三个书签。

02

卡片收集、课堂风采、账户总览必须分开，避免页面信息互相挤压。

03

这份需求体现的产品判断：孩子看收藏，老师看记录和小队总览，三类信息不能混在一个列表里。

1. 背景

现在成长页已经改成一本书的形式。

左侧用书签切换三类内容：

  1. 卡片收集册
  2. 成长记录册
  3. 小队总览

这说明数据链路也要跟着改。后端不能只返回一个成长列表，而要支持三个明确的数据视图。

2. 问题定义

如果成长中心仍然把纪念卡、成长卡、星星、经验、宝石、最近表现全部混在一起，会出现几个问题：

  1. 卡片收集册被数据总览挤占空间。
  2. 成长记录册看起来像普通列表，没有课堂风采展示感。
  3. 老师想看小队总览时，要从卡片和记录里找数据。
  4. 前端无法稳定做书本式UI，因为后端数据没有分层。

3. 目标

成长中心要形成一个清楚的数据结构：

  1. 卡片收集册：回答“我收集到了什么”。
  2. 成长记录册：回答“每堂课发生了什么”。
  3. 小队总览：回答“这个小队整体成长到哪里了”。

三类内容同属成长中心，但数据职责要分开。

4. 版本范围

本需求覆盖：

  1. 成长中心书本式页面
  2. 左侧三类书签
  3. 卡片收集册按主题切换
  4. 成长记录册展示每堂课程风采
  5. 小队总览展示聚合数据
  6. 纪念卡、成长卡、奖励账户之间的数据关系

5. 方案设计

5.1 卡片收集册

默认进入成长中心时，先展示卡片收集册。

页面顶部中间有课程主题切换，例如：

  • 生命科学
  • 自然科学
  • 工程科学
  • 社会人文

每个主题下展示完整课程卡位：

  • 已获得：显示卡面、课程名、获得时间、普通卡/闪卡状态。
  • 未获得：显示锁定或未收集状态。

5.2 成长记录册

成长记录册展示每堂课程的风采展示。

每条记录至少包含：

  • 课程名称
  • 课程主题
  • 完成时间
  • 成长卡摘要
  • 星星/经验/宝石奖励
  • 能力标签或课堂高光

前端不展示上课照片，但后端可以保留照片或动作数据key用于后续分析。

5.3 小队总览

小队总览单独放一个书签，不再挤在卡片收集册或成长记录册旁边。

总览展示：

  • 纪念卡数量
  • 累计星星
  • 累计经验
  • 当前宝石
  • 完成课程数
  • 最近表现

6. 关键规则

6.1 发卡规则

首次完成某节课，发一张对应的纪念卡。

重复上同一节课，不重复获得同一张纪念卡。

6.2 闪卡规则

每个主题可以存在闪卡状态。V1可以先由规则判断，例如本主题表现最好或星星收集满的课程卡升级为闪卡。

6.3 数据归属规则

所有纪念卡、成长卡、星星、经验、宝石都归属当前小队，不归属母账号全局，也不归属单个学生。

6.4 展示规则

卡片收集册、成长记录册、小队总览必须分别查询和展示，不能把总览数据挤进卡片或记录内容区。

7. 数据要求

建议成长中心返回一个聚合结构：

  1. overview：小队聚合数据。
  2. card_album：按主题分组的卡片收集状态。
  3. growth_records：按课程完成记录生成的成长卡列表。

每张卡至少包含：

  1. card_id
  2. course_id
  3. theme_id
  4. 课程名
  5. 卡面视觉key
  6. owned状态
  7. is_flash_card
  8. earned_at

每条成长记录至少包含：

  1. lesson_record_id
  2. course_id
  3. 完成时间
  4. 成长卡摘要
  5. 奖励数据
  6. 能力标签

8. 验收标准

  1. 成长中心默认进入卡片收集册。
  2. 卡片收集册能按课程主题切换。
  3. 每个主题下能看到已收集和未收集卡片。
  4. 重复上课不会重复发卡。
  5. 成长记录册展示每堂课的成长卡/风采内容。
  6. 小队总览是独立书签，不挤占卡片和记录页面。
  7. 三类数据都按当前team_id过滤。

9. 暂不纳入

这轮先不做：

  1. 复杂算法评定最佳课。
  2. 多人社交交换卡片。
  3. 家长端成长报告。
  4. 完整动作数据可视化。

先把“卡片收集 + 课堂记录 + 小队总览”这条基本链路跑通。
