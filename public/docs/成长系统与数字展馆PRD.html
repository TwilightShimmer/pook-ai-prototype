成长系统与数字展馆PRD

阅读说明 先看结论，再看细节。

这份文档围绕《成长系统与数字展馆PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

这份需求在解决：只有成长记录还不够，缺少可收藏、可展示、可持续激励的成果体系问题。

02

这份需求值得做：它能同时增强孩子的收集感、家长的感知度和机构的长期复课动力。

03

这份需求体现的产品判断：成长负责记录过程，数字展馆负责收藏成果，这两套系统应该拆开设计。

1. 背景

我认为只做“成长记录”还不够。 还应该再加一个“数字展馆”。

原因很简单：

  1. 成长页解决的是过程记录
  2. 数字展馆解决的是成果收藏

这两个东西不一样。 应该拆开做。

2. 问题定义

如果只有成长记录页，会有几个问题：

  1. 孩子缺少可收集的成果感
  2. 单节课结果不够有记忆点
  3. 家长看到的是记录，不一定能感知收藏和高光
  4. 课程之间缺少长期积累机制

3. 目标

我希望同时建立两套系统：

  1. 成长系统：记录上课过程
  2. 数字展馆：收藏课堂成果

一句话说：

成长解决“我学了什么”，展馆解决“我收集到了什么”。

4. 版本范围

本需求覆盖：

  1. 成长页
  2. 数字展馆页
  3. 纪念卡发放规则
  4. 闪卡升级规则
  5. 与课堂闭环的衔接方式

5. 方案设计

5.1 成长页

定位：

  • 上课过程记录页

主要回答：

  • 我上过什么课
  • 我做了什么
  • 我有哪些表现

适合承载：

  • 上课时间线
  • 完成任务
  • 作品照片
  • 能力标签
  • 课堂评价

5.2 数字展馆页

定位：

  • 纪念卡收藏页

主要回答：

  • 我收集到了什么
  • 哪些课我已经完成了
  • 哪张卡是这个主题里最亮眼的

适合承载：

  • 课程纪念卡
  • 普通卡 / 闪卡
  • 主题分馆
  • 收集进度

6. 关键规则

6.1 发卡规则

每上完一节课，发一张对应的纪念卡。

例如：

  • 上完“犀牛洗澡”
  • 发一张“犀牛卡”

6.2 重复上课规则

重复上同一节课，不重复获得卡片。

6.3 闪卡规则

每上完一个主题的课程后， 把这个主题里表现最好的一节课对应的卡，升级为闪卡。

6.4 闪卡数量规则

建议：

每个主题最多 1 张闪卡

6.5 重复上课后的处理

建议：

  • 不重复发普通卡
  • 但允许刷新“主题最佳”

7. 数据要求

每张卡至少包含：

  1. 课程名
  2. 主题名
  3. IP / 课程图案
  4. 获得日期
  5. 卡片状态

建议预留：

  1. 作品图缩略图
  2. 课程徽章
  3. 高光标签

8. 验收标准

  1. 每节课结束可发一张纪念卡
  2. 重复上课不会重复发卡
  3. 每个主题最多 1 张闪卡
  4. 成长页和数字展馆页职责分开
  5. 孩子可以清楚看到“我完成了什么”和“我收集到了什么”

9. 暂不纳入

这轮先不做：

  1. 复杂算法评定最佳课
  2. 多人社交交换卡片
  3. 大型展馆互动玩法

先把“记录 + 收藏 + 高光”这条基本链路跑通。
