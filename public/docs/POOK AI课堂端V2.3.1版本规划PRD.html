Version Roadmap / Product PRD

POOK AI课堂端 V2.3.1版本规划PRD

V2.3.1 不重新推翻 V1，而是在 V1 的课堂闭环上补齐更像“AI课堂产品”的能力：课堂智能反馈、成长记录增强、兑换履约状态、过程数据沉淀。

阅读说明 先确认“这个版本不做什么”，再拆开发任务。

这份文档不是老板汇报稿，也不是全量 V2 蓝图。它的作用是把下一个可交付版本切出来，方便产品、前端、后端、UI 对齐。

  • V1 先跑通：登录、小队、选课、上课、奖励、成长、商城兑换。
  • V2.3.1 增强：课堂评价、Agent 状态、成长筛选导出、兑换履约、数据采集闭环。
  • 更重的能力：学生个人档案、家长端、完整报表、课程后台编辑器，放到后续版本。

1. 文档目的

回答一个核心问题：

我们在 PRD 里确实写过“下个版本要做什么”，但内容分散在多份文档里。V2.3.1 要把这些内容收束成一个明确版本。

这份 PRD 用来对齐：

  1. V2.3.1 的版本定位。
  2. 哪些能力进入本版本。
  3. 哪些能力暂时不做。
  4. 前端、后端、UI、测试分别需要交付什么。
  5. 数据链路如何从 V1 的“能记录”升级到 V2.3.1 的“能分析、能展示、能运营”。

3. V2.3.1 版本定位

版本性质V1 后的增强版本
核心目标让课堂数据真正可用
产品关键词智能反馈 / 成长沉淀 / 运营闭环
不做方向不重做整套系统

我建议把 V2.3.1 定义为：

在不推翻 V1 课堂闭环的前提下，补齐课堂智能评价、过程数据沉淀、成长中心增强、积分商城履约这四件事。

这个版本不应该直接跳到“完整 V2 大平台”。否则范围会失控，开发排期也会变得很难落地。

5. 模块需求

5.1 课程表现评价

课程奖励领取完成后，系统生成本次课堂评价。评价不面向单个孩子，仍然以小队为最小单位。

  • 评价维度：参与度、合作度、表达度、动手完成度、专注表现。
  • 评价形式：短文本总结 + 能力标签 + 可选分数。
  • 展示位置：成长中心 > 成长记录册。
  • 数据归属：按 team_id、course_id、lesson_record_id 绑定。
  • 兜底规则：AI 评价失败时，使用规则模板生成基础评价，不能导致课程结束失败。

5.2 Agent 状态可见

POKI 的状态要从“页面效果”变成“课堂运行状态”。

状态 含义 前端表现 是否记录事件
Ready准备进入任务POKI 待机、提示当前任务是
Watching正在观察画面视频框出现观察动效是
Listening正在听孩子回答麦克风/声波动效是
Thinking正在判断或生成反馈POKI 思考动效是
Result给出反馈或进入下一步奖励、提示、下一步动作是

5.3 课堂提示与反馈增强

本版本重点不是让 LLM 随意控制课堂，而是让系统在关键时刻能自动给出低龄友好的提示。

  • 进入环节：POKI 简短说明“现在要做什么”。
  • 等待回答：如果孩子长时间无响应，换一种更简单的问法。
  • 找积木：找错时提示颜色、数量或再看一眼，不做惩罚。
  • 多人协作：提示轮到几号小朋友，避免一个孩子一直操作。
  • 环节完成：给出鼓励、星星、经验或下一步提示。

5.4 成长中心增强

成长中心已经改成一本书。V2.3.1 要让这本书的数据更好查、更好复盘。

  • 卡片收集册：按主题展示卡片，支持普通卡、闪卡、未解锁状态。
  • 成长记录册：按主题、课程、时间筛选每堂课的风采记录。
  • 小队总览：展示累计星星、经验、宝石、课程完成数、最近表现。
  • 导出基础版：老师可以导出某个小队的一段时间成长记录。

5.5 积分商城履约状态

V1 已经定义“每个商品每个小队只能兑换一次”。V2.3.1 需要补齐兑换后的发放状态。

  • 兑换完成后，按钮变成“已售罄”。
  • 后台或教师端可看到发放状态：待发放、已发放、已完成。
  • 不做物流，不做家长支付，不做复杂库存系统。
  • 商品仍然由教师通过数学验证码确认兑换，避免儿童误操作。

6. 数据链路建议

V2.3.1 的数据目标是：不仅知道“完成了”，还知道“课堂中发生了什么、表现如何、奖励是否真正完成”。

6.1 新增或增强数据对象

对象 用途 关键字段建议
lesson_evaluation 课程表现评价 evaluation_id, lesson_record_id, team_id, course_id, summary, tags, scores, generated_at
lesson_event 课堂过程事件 event_id, lesson_record_id, stage, event_type, payload, occurred_at
agent_state_event POKI 状态记录 state, stage, started_at, ended_at, reason
exchange_fulfillment 兑换履约 exchange_id, team_id, item_id, fulfillment_status, operator_id, fulfilled_at
growth_export_task 成长记录导出 task_id, team_id, date_range, status, file_url, created_by

6.2 数据归属原则

  1. 本版本仍然以小队为最小数据单位，不做学生个人长期档案。
  2. 课程表现评价绑定 lesson_record_id，不能只绑定课程。
  3. 成长记录、纪念卡、经验、宝石、兑换状态全部按 team_id 归属。
  4. 照片、动作数据可以存储 key，但不在前端成长中心直接展示。
  5. 导出能力必须受教师权限控制，儿童端不能触发。

8. 验收标准

产品验收

  • 完成一节课后，成长记录册能看到本次课程表现评价。
  • 评价内容是小队维度，不出现学生个人长期档案。
  • 成长中心可以按主题、课程、时间筛选记录。
  • 卡片收集册、成长记录册、小队总览三类内容不混在一起。
  • 商城兑换后能看到发放状态，不只是“扣宝石”。

前端验收

  • POKI 状态有统一视觉组件，不同页面不能各做各的。
  • Ready / Watching / Listening / Thinking / Result 状态切换有明确动效。
  • 成长记录筛选不挤压卡片册和总览页布局。
  • 导出、发放状态、教师操作入口必须有儿童防误触设计。

后端验收

  • 课程完成后能稳定生成或兜底生成 lesson_evaluation。
  • 课堂过程事件能按 lesson_record_id 查询。
  • 成长中心接口按 team_id 过滤，不串小队数据。
  • 重复上课不重复发纪念卡和经验，但可按规则发放少量宝石。
  • 兑换商品每个小队只能购买一次，已兑换商品返回已售罄或等价状态。

9. 暂不纳入 V2.3.1

这些方向有价值，但不建议塞进 V2.3.1：

  1. 学生个人档案。
  2. 家长端。
  3. 完整运营报表。
  4. 课程后台编辑器。
  5. 多老师账号与复杂权限分级。
  6. 完整动作数据可视化大屏。
  7. 线上支付、H5 收银台、物流系统。
  8. 全国排行榜或跨机构对比。
V2.3.1 的价值不是“功能越多越好”，而是把 V1 产生的数据变成可反馈、可复盘、可运营的课堂资产。
