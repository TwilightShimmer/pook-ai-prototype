积分商城与实物奖励兑换PRD

阅读说明 先看结论，再看细节。

这份文档围绕《积分商城与实物奖励兑换PRD》展开，重点不是堆功能，而是把模糊讨论收口成可判断、可协作、可开发或可验收的产品依据。

  • 简单摘要：先确认本文解决的问题、核心结论和适用版本。
  • PM价值：把真实场景、用户问题、业务规则和执行边界讲清楚，减少团队理解偏差。
  • 使用方式：老板看结论和风险，设计看页面目标，开发看规则和验收口径。

价值摘要

01

这份需求在解决：课堂积分目前只有累计，没有一个孩子能立刻理解的使用出口。

02

这份需求值得做：它能把上课、积分、奖励、复课动力串成一条更完整的闭环。

03

这份需求体现的产品判断：低龄激励不能只停留在数字增长，最好能落到可兑换、可带走的小实物奖励上。

1. 背景

我认为商业化系统里，除了卖套件，还应该在最下面加一个积分商城。 孩子上完课拿到的宝石积分，应该可以兑换：

  1. 贴纸
  2. 勋章
  3. 卡片
  4. 其它实物小奖励

这样积分才不是空的。

2. 问题定义

如果积分只在页面上增长，不和具体奖励绑定，会有几个问题：

  1. 孩子不知道积分到底有什么用
  2. 家长看不到积分和真实激励之间的关系
  3. 商业化页只有售卖感，缺少课堂成果转奖励的连接
  4. 长期复课动力不够具体

3. 目标

做一个放在商业化系统底部的积分商城。

它要完成三件事：

  1. 让积分有明确用途
  2. 让孩子看到“再上一节课就能换到什么”
  3. 让商业化系统不只是购买入口，也承接课堂奖励

4. 版本范围

本轮先覆盖：

  1. 商城页底部新增积分商城区域
  2. 展示可兑换实物小奖励
  3. 显示每个奖励所需积分
  4. 积分足够时可兑换
  5. 兑换前增加二级确认密码
  6. 兑换成功后扣减积分
  7. 已兑换奖励显示状态

5. 方案设计

5.1 页面位置

积分商城放在商业化页最下方。 上方继续保留套件售卖内容。 下方新增积分兑换区。

5.2 商品类型

优先放三类：

  1. 贴纸
  2. 勋章
  3. 卡片

如有需要，再扩展礼包类奖励。

5.3 页面表达

每个奖励卡片至少展示：

  1. 奖励名称
  2. 奖励类型
  3. 所需积分
  4. 一句简短说明
  5. 兑换按钮

5.4 二级确认设计

点击兑换后，不直接扣积分。 先弹出二级确认层。

二级确认不使用简单 4 位数字密码。 改用更复杂的验证方式，例如：

  1. 乘除法
  2. 先加后乘的混合算式
  3. 需要成人协助完成的简单计算题

目的很明确：

保障儿童难以误兑换、误购买。

6. 关键规则

6.1 兑换规则

积分足够才允许兑换。 兑换成功后，立即扣减积分。

6.2 重复兑换规则

本轮建议：

同一奖励默认只允许兑换一次

这样先保证规则简单，也避免测试期被刷穿。

6.3 风险控制规则

任何兑换动作都必须经过二级确认。 未通过验证，不允许完成兑换。

6.4 提示规则

需要明确给出四类反馈：

  1. 积分不足
  2. 验证失败
  3. 兑换成功
  4. 已兑换过

6.5 奖励方向规则

奖励应优先选择：

  1. 小而具体
  2. 孩子拿得到
  3. 家长容易理解价值

不建议一开始就做过大、过重、过复杂的奖励。

7. 数据 / 状态要求

每个兑换商品至少包含：

  1. id
  2. 名称
  3. 类型
  4. 所需积分
  5. 说明文案
  6. 状态

用户侧至少需要记录：

  1. 当前积分余额
  2. 已兑换奖励列表
  3. 当前二级确认状态

8. 验收标准

  1. 商业化页底部存在积分商城区域
  2. 至少可展示贴纸、勋章、卡片三类奖励
  3. 每个奖励明确显示积分成本
  4. 积分不足时不可兑换，并有反馈
  5. 点击兑换后必须先进入二级确认
  6. 二级确认失败时不会扣减积分
  7. 二级确认成功后才会完成兑换
  8. 兑换成功后会扣减积分，并更新状态
  9. 已兑换奖励不会重复兑换

9. 暂不纳入

这轮先不做：

  1. 实物库存系统
  2. 发货系统
  3. 家长账号独立确认流程
  4. 限购周期规则
  5. 更复杂的积分来源算法

先把“积分有出口 + 儿童难以误操作”这条链路跑通。
